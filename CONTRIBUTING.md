# Contributing

Thanks for taking the time to look at one of my projects.

## Before opening an issue

- Search the existing issues and the README first.
- Try the latest release; older builds may already contain the fix.
- For a bug, include the release version, your OS, the exact steps to reproduce, and the relevant log output.
- For a feature request, describe the problem you are trying to solve rather than only the implementation you have in mind.

## Pull requests

- Keep a pull request focused on one change.
- Match the existing code style and project layout.
- Add or update tests when the project has a test suite.
- Update the README or docs if behaviour changes.
- Describe what you tested and on which platform.

Small fixes and documentation improvements are welcome. For a large change, please open an issue first so we can agree on the direction before you spend a lot of time on it.

## Commits

Conventional Commits (`feat:`, `fix:`, `docs:`, `chore:`) are appreciated but not required. A clear one-line summary matters more than the prefix.
