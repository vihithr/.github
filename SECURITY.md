# Security Policy

## Supported versions

Security fixes are applied to the latest release of each project. Older builds
are not maintained unless the repository says otherwise.

## Reporting a vulnerability

Please **do not open a public issue** with exploit details.

Use GitHub's private reporting flow instead:

1. Open the affected repository.
2. Go to **Security** → **Report a vulnerability**.
3. Include the repository, version or commit, a description of the issue, and
   the steps to reproduce it.

If a repository does not have private reporting enabled, open an issue asking
for a private channel and leave the details out of the public thread.

## What to include

- The affected project and version.
- Your platform and runtime.
- A minimal reproduction or proof of concept.
- The impact you believe the issue has.
- Any suggested fix, if you have one.

## Scope

This policy covers the source code and release binaries published from my
repositories. It does not cover third-party dependencies, game files, API
providers, or hardware that the project only controls indirectly.

## Disclosure

I will acknowledge a report as soon as I can, keep you updated on the fix, and
credit you in the release notes unless you prefer to stay anonymous.
